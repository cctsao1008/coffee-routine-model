# Tiny Transition Weather 🌦️🎲☕

The original hybrid model used one fixed transition table:

```text
p(m[t+1] | m[t])
```

That baseline is still preserved exactly.

The optional context-aware transition model asks a slightly richer question:

```text
p(m[t+1] | m[t], x[t], a[t], d[t], regime[t])
```

where the extra context is explicit and inspectable.

## Tiny context features 🧺

The first hand-set prototype uses:

```text
friction
unpredictability
low mutuality
coordinated exception
recovery evidence
special-event signal
external disturbance
explicit regime logits
```

The state-derived features come from the current particle state. Action-derived features come only from observable `RoutineActions`. External context such as a known special event or disturbance must be supplied explicitly.

```text
Context != telepathy.
Context != deterministic mode choice.
```

## How the dice move 🎲

For a previous mode `i`, start with the old transition row:

```text
base = P_fixed[m[t]=i, :]
```

Then add bounded context nudges in log-probability space:

```text
logit_next
    = log(base)
    + feature_vector @ feature_effects
    + regime_logits
```

The total nudge for every target mode is clipped before softmax normalization.

So one context event may change the distribution, but cannot force:

```text
P(next mode = something) = 1
```

Tiny dice still roll. XD

## A few semantic guardrails 🌱

- a voluntary `pass` alone does **not** secretly become Leave evidence
- ordinary delivery + acknowledgment does **not** secretly become Recovery evidence
- `Special` needs explicit special-event context rather than guessing from a callback
- coordinated exception sync can make Leave more plausible without declaring failure
- explicit closure / recovery hints can make Recovery more plausible
- a regime detector may supply target-specific `regime_logits`, but a regime change alone does not invent its direction

## Fixed baseline stays available 🧺

`CoffeeParticleFilter` keeps fixed transitions by default.

Context-aware mode dynamics are opt-in:

```python
from coffee_brain.transitions import DEFAULT_CONTEXT_TRANSITIONS

pf = CoffeeParticleFilter(
    transition_config=DEFAULT_CONTEXT_TRANSITIONS,
)
```

Then a transition may receive:

```python
pf.update(
    observation,
    actions=actions,
    transition_context=context,
)
```

This preserves old reproducible baskets while giving P2 experiments a richer mode model.

```bash
  --days 400 \
  --seed 20260908
```


```text
runtime-independent daily trace
```

and paints `transition-race.png`.

Because the synthetic truth is generated by the context model, this benchmark checks whether the implementation can recover the advantage it is supposed to have. It is **not** independent real-world validation.
